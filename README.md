# ZART · OPC 方法编年

> **一句话**：把「写在文档里的规矩」变成「机器查得到的规矩」——一套由 AI 编写的人机协作方法（OPC，AI-collaboration Operating Method）的事故—对策编年史。

[打开交互演示页](index.html) · [参与讨论](../../issues) · [提出一条新记录](../../issues/new/choose)

---

## 这是什么

这是一个**可点选、可筛选、可讨论的静态网页**，用七周的真实改造记录讲清一件事：

> 每撞一次墙，就把教训从一句话升级成「执行者开工必读 + 机器自动检查 + 编号落账」的三处落点。

反复出现的病是同一句：**规矩写在给老板看的文档里，执行的人读不到、机器也不查，所以等于没定。**
反复出现的解法也是同一句：**让机器查得到才算数。**

页面里有：

- **三层机制地图**：记忆层 / 项目管理层 / 多智能体层，各一句话讲清。
- **46 条编年记录**：七阶段，每条固定四列——发现了什么问题、怎么解决的、用了什么方法、示例编号。可按类别筛选、关键词搜索、点开看完整因果。
- **12 条方法原型**：从每次事故里复用出来的同一套动作，可单独抽成方法论。
- **发车闸模拟器**：勾一勾四个条件，看结论在「拦下 / 可放行」之间切换，直观演示为什么绿灯必须有坏样本。

### 这不是什么

- 不是某个真实团队的内部制度或档案；
- 不是产品文档、不是开发计划、不是任何可核实的业务事实；
- 页面里的 `A-01 / P-12 / PL-01 / E-05 / R-07 / T-01` **都是示例编号格式，由 AI 编写**，不对应任何真实记录。

## 12 条方法原型（速览）

| # | 方法 | 一句话 |
|---|---|---|
| 1 | 三处落点 | 新规矩必须落在开工必读处、机器检查、编号落账，缺一处视为没定 |
| 2 | 绿灯要有坏样本 | 说通过要同时拿出坏样本被挡住的证明 |
| 3 | 同机同数据对照组 | 判断新失败还是老毛病，要同机同数据同刻先跑基线 |
| 4 | 新失败零豁免 | 新出现的失败挡住发布，谁签字都不行 |
| 5 | 读账本 + 决策关卡 | 决策前机器核对该读的读没读，缺就拒绝 |
| 6 | 分层预算 | 必读只有短件，大账本只按关键词查 |
| 7 | 原文照常加载 | 记忆要治的是理解偏差，不是膨胀本身 |
| 8 | 时间锚点代替「现行」 | 只认 UTC 时间戳，取代关系必须写清 |
| 9 | 单一库存表 + 孤儿扫描 | 做完的件必须有唯一去处，孤儿直接接闸 |
| 10 | 需求当轮入池 | 随口需求当轮登记，按轻重缓急捞，还要找得到 |
| 11 | 派工自带接班块 | 你是谁、先读哪、上一断点、当前队列 |
| 12 | 裁决后接线 | 没有编号的结论不算裁决；机制故障不排队 |

## 快速开始

### 本地看

直接双击 `index.html` 即可。无构建、无依赖、无后端、无网络请求、无追踪脚本。

### 发布到网上

仓库已带两套零配置托管方案，任选其一：

- **GitHub Pages**：仓库 Settings → Pages → Source 选 `GitHub Actions`，推送后 `.github/workflows/deploy.yml` 自动部署。
- **Cloudflare Pages**：连接仓库，构建命令留空、输出目录填 `.`（或直接用 `wrangler.toml`：`npx wrangler pages deploy .`）。

### 挂自己的域名 / 讨论区

`index.html` 顶部「发布配置」区已预填两套链接（GitHub Pages 与 Issues）；换域名或换讨论区时只改这两行：

```js
const SITE_URL = 'https://owenjiong24.github.io/zart-opc-method/';
const DISCUSS_URL = 'https://github.com/OwenJiong24/zart-opc-method/issues';
```

留空则不显示对应链接。其余内容不要改。

## 参与讨论

这个仓库的目的就是**被讨论、被补充、被反驳**：

- 想加一条编年记录：用 [新增一条编年记录](../../issues/new?template=new-entry.md) 模板，按「发现 / 解决 / 方法 / 编号」四格填写。
- 发现方法有问题或有更好的做法：用 [指出问题或提出改进](../../issues/new?template=challenge.md) 模板。
- 想深挖某一条：在对应 Issue 里引用条目编号（如 `阶段 3 · 全绿上线后功能丢失`）开新讨论。

**贡献纪律**（和页面里讲的方法一致）：

1. 只写公开的、可讨论的经验，不贴任何真实项目的内部文件、主机名、域名、账号、凭据、客户数据。
2. 新编号一律用示例格式 `A-## / P-## / PL-## / E-## / R-## / T-##`，并注明「AI 编写的示例」。
3. 一条记录只讲一件事，四格写全；主张要有反面例子或失败场景支撑。
4. 作者不自审：新增记录请另一位贡献者或不同模型系复核后再合并。
